# 法人组织管理模块 - 实施总结

## 📋 实施概述

本次实施完成了**法人组织管理**功能模块，并与现有的**客户档案**模块建立了关联关系。法人组织用于管理客户的法人层级关系（如：集团-子公司-工厂），与客户内部组织（部门架构）是完全不同的概念。

## 🔄 数据关联关系

### 法人组织 → 客户档案

- 一个法人组织可以关联一个客户档案
- 客户档案记录 `legalEntityId` 关联到法人组织
- 关联后可以查看组织路径和集团内其他客户

### 集团 → 客户

- 同一集团下可以有多个客户（不同层级的组织节点）
- 可以查看集团内所有客户列表
- 客户列表支持按集团筛选

### 创建流程

```
方式1：先创建法人组织，再创建客户
  法人组织列表 → 选择组织 → 创建客户 → 自动关联

方式2：直接创建客户，可选关联法人组织
  客户档案 → 新建客户 → 选择法人组织（可选） → 保存
```

## 🎯 核心业务规则

### 1. 组织编号规则

- 格式：`LE-YYYYMMDD-XXX`
- 自动生成，全局唯一

### 2. 层级限制

- 支持无限层级嵌套
- 建议不超过10层

### 3. 删除检查

- 有子组织时不可删除
- 已关联客户时不可删除

### 4. 循环引用检查

- 不允许设置会导致循环引用的上级组织
- 设置上级时自动检查

### 5. 客户关联

- 一个法人组织只能对应一个客户
- 一个客户只能关联一个法人组织

### 6. 数据来源

- 手动录入、第三方接口、批量导入
- 标记数据来源

## ⚠️ 注意事项

1. **术语统一**
   - "法人组织" = 独立法人实体的层级关系（本模块）
   - "内部组织" = 客户内部的部门架构（客户档案模块）

2. **数据一致性**
   - 法人组织和客户档案是关联而非包含关系
   - 删除法人组织不会删除关联的客户档案
   - 客户档案可以不关联法人组织

3. **权限控制**
   - 法人组织作为基础数据，所有人可见
   - 客户档案受业务权限控制

4. **性能考虑**
   - 大型集团可能有数百个组织节点
   - 树形结构采用虚拟滚动（如需要）
   - 支持异步加载子节点（如需要）
