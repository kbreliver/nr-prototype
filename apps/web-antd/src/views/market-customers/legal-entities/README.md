# 法人组织管理模块

## 功能概述

法人组织管理模块用于管理客户的法人组织层级关系（集团-子公司-工厂等），与客户内部组织（部门架构）是不同的概念。

### 核心概念

- **法人组织**：独立的法人实体，可以是集团、子公司、分公司、工厂等
- **组织层级**：法人组织之间的上下级关系（如：集团 > 子公司 > 工厂）
- **客户关联**：法人组织可以关联到客户档案，但不是所有组织节点都会成为客户

### 与客户内部组织的区别

| 对比项 | 法人组织 | 客户内部组织 |
|--------|----------|--------------|
| 独立法人 | ✓ 是独立法人实体 | ✗ 不是独立法人 |
| 签订合同 | ✓ 可以独立签订合同 | ✗ 不能独立签订合同 |
| 管理范围 | 集团层级关系 | 客户内部部门架构 |
| 是否都是客户 | ✗ 不一定 | ✗ 不是客户 |

## 功能特性

### 1. 法人组织列表
- 树形结构展示组织层级
- 左侧树形导航，右侧详情展示
- 支持搜索和筛选
- 标识哪些节点已创建客户
- 快速操作：添加子组织、编辑、删除

### 2. 法人组织详情
- 基本信息管理
- 组织层级可视化
- 关联客户信息
- 集团客户列表

### 3. 数据来源
- 手动录入
- 第三方接口（企查查、天眼查等）
- 批量导入

### 4. 与客户档案关联
- 客户可以关联到法人组织节点
- 从法人组织快速创建客户
- 查看同一集团下的所有客户

## 数据模型

### LegalEntity（法人组织）

```typescript
interface LegalEntity {
  id?: number;
  entityCode: string;              // 组织编号
  entityName: string;              // 组织名称
  creditCode?: string;             // 统一社会信用代码
  legalRepresentative?: string;    // 法定代表人
  registeredCapital?: string;      // 注册资本
  establishDate?: string;          // 成立日期
  address?: string;                // 注册地址
  parentEntityId?: number;         // 上级组织ID
  entityLevel: number;             // 层级（1,2,3...）
  entityType: LegalEntityType;     // 组织类型
  isCustomer: boolean;             // 是否已创建客户
  customerId?: number;             // 关联的客户ID
  dataSource: DataSource;          // 数据来源
  children?: LegalEntity[];        // 子组织
}
```

## 业务规则

### 1. 组织编号规则
- **格式**：LE-YYYYMMDD-XXX（自动生成）
- **唯一性**：全局唯一

### 2. 层级规则
- **最大层级**：建议不超过10层
- **层级计算**：自动根据上级组织层级+1
- **根节点**：层级为1（无上级组织）
- **根节点类型限制**：只有"集团总部"和"公司"可以作为根节点

### 3. 组织类型层级关系规则

**可作为根节点的类型：**
- ✓ 集团总部
- ✓ 公司
- ✗ 子公司（必须有上级）
- ✗ 分公司（必须有上级）
- ✗ 办事处（必须有上级）
- ✗ 工厂（必须有上级）

**组织类型说明：**
- **集团总部**：大型企业集团的最高层级组织
- **公司**：独立的公司法人实体
- **子公司**：上级公司控股的子公司，支持多层嵌套
- **分公司**：上级公司的分支机构
- **办事处**：区域代表处或办事机构
- **工厂**：生产制造基地

**典型组织结构：**
```
集团总部
├── 公司
│   ├── 子公司
│   │   ├── 分公司
│   │   └── 工厂
│   └── 办事处
└── 工厂
```

### 4. 删除检查
- 有子组织时不可删除
- 已关联客户时不可删除

### 5. 循环引用检查
- 不允许设置会导致循环引用的上级组织
- 不能将组织设置为自己或自己下级的子组织

### 6. 唯一性约束
- 统一社会信用代码在系统中唯一

### 7. 客户关联
- 一个法人组织只能对应一个客户
- 一个客户只能关联一个法人组织

## 使用场景

### 场景1：管理集团客户的组织结构

```
中国建材集团（集团总部）
├── 北方建材公司（子公司）- 是客户 ✓
│   ├── 北京水泥厂（工厂）- 是客户 ✓
│   ├── 天津建材厂（工厂）- 不是客户 ✗
│   └── 河北石材厂（工厂）- 是客户 ✓
└── 南方建材公司（子公司）- 是客户 ✓
    └── 广州玻璃厂（工厂）- 不是客户 ✗
```

### 场景2：从法人组织创建客户

1. 在法人组织管理中录入/导入组织信息
2. 选择某个组织节点
3. 点击"创建客户"按钮
4. 系统自动填充基础信息（名称、信用代码、法人、注册资本等）
5. 完善客户业务信息
6. 保存后自动建立关联关系

### 场景3：查看集团客户全景

1. 进入某个客户详情页
2. 查看关联的法人组织
3. 查看组织路径（如：集团 > 子公司 > 工厂）
4. 查看同一集团下的其他客户
5. 快速跳转到相关客户

## 注意事项

1. **数据一致性**：法人组织和客户档案是关联而非包含关系
2. **删除影响**：删除法人组织不会删除关联的客户档案
3. **权限控制**：法人组织作为基础数据，所有人可见
4. **性能考虑**：大型集团可能有数百个组织节点，需要考虑虚拟滚动和异步加载
