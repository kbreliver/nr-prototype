## 2. 功能目标与核心价值

### 2.1 功能目标

客户档案模块旨在为销售团队、市场团队、服务团队提供统一的客户信息管理平台。通过建立完整的客户档案，记录客户基本信息、组织架构、联系人信息、业务往来历史等，实现客户信息的标准化管理和全方位视图，为客户关系管理、商机跟进、项目实施、运维服务等业务提供数据支撑。

**主要目标：**
- 建立统一的客户主数据管理体系
- 支持客户信息的全方位维护与查询
- 实现客户组织层级的可视化管理
- 建立客户联系人网络，便于业务沟通
- 支持客户分类与标签管理，便于精准营销
- 为后续商机管理、方案配置、项目实施提供客户信息支撑

### 2.2 核心价值

**对客户：**
- 获得更加精准和个性化的服务
- 减少重复沟通成本
- 享受连贯一致的服务体验

**对公司：**
- 建立完整的客户信息库，避免信息孤岛
- 提升客户信息的准确性和完整性
- 支撑精准营销和客户细分
- 便于客户关系维护和商机挖掘
- 为业务决策提供数据支持

**对集团：**
- 形成统一的客户管理标准
- 支撑客户资源的整合与共享
- 提升集团整体客户服务水平

## 3. 业务背景与使用场景

### 3.1 背景说明

随着公司业务的快速发展，客户数量不断增长，客户信息管理面临以下挑战：
- 客户信息分散在各个部门和系统中，缺乏统一管理
- 客户基本信息不完整、不准确，影响业务开展
- 客户组织架构不清晰，对接人员不明确
- 联系人信息更新不及时，沟通效率低下
- 缺乏客户分类和标签体系，难以进行精准营销
- 客户业务历史记录不完整，影响服务质量

为解决上述问题，需建设统一的客户档案管理模块，实现客户信息的标准化、完整化、可视化管理。

### 3.2 使用场景

| 场景编号 | 场景名称 | 场景说明 | 典型用户 |
|---------|---------|----------|---------|
| S01 | 新客户录入 | 销售人员获取新客户信息后，在系统中创建客户档案 | 销售人员、市场人员 |
| S02 | 客户信息维护 | 定期更新客户基本信息、联系方式、业务状态等 | 销售人员、客服人员 |
| S03 | 客户组织架构管理 | 维护客户的组织层级结构，明确各部门职能和对接人 | 销售经理、项目经理 |
| S04 | 客户联系人管理 | 维护客户关键联系人信息，建立沟通网络 | 销售人员、客服人员 |
| S05 | 客户查询与检索 | 根据客户名称、行业、地区等条件快速查找客户 | 所有用户 |
| S06 | 客户分类与标签 | 为客户打标签，进行客户分类和分级管理 | 销售经理、市场经理 |
| S07 | 客户业务历史查询 | 查看客户的商机、方案、合同、项目等业务历史 | 销售人员、项目经理 |

#### 三、功能点说明

- 支持按关键字（客户名称或编号）、所属行业、客户级别、客户状态等条件搜索
- 关键字搜索支持模糊匹配，同时匹配客户名称和客户编号
- 列表每行前含复选框，支持批量选择和批量删除
- 批量删除按钮在左上角，选中客户后才可用，未选中时禁用状态
- 导出按钮在右上角靠右显示，与其他列表页保持一致
- 所有列均支持升序/降序排序
- 每页显示 20 条数据，可分页查看（支持10/20/50/100条切换）
- 支持导出为 Excel（下一期功能）
- 点击客户编号可进入详情页
- 客户级别采用颜色标签展示（重点客户-红色、普通客户-蓝色、潜在客户-灰色）
- 客户状态采用颜色标签展示（合作中-绿色、意向客户-蓝色、已流失-灰色）
- 新建客户采用弹框形式，填写核心字段后创建，再跳转详情页完善信息
- 搜索区域精简优化，提升检索效率

#### 四、关键操作流程

**新建客户流程**：
1. 用户点击"新建客户"按钮
2. 弹出新建客户对话框
3. 用户填写客户名称（必填）、客户简称、统一社会信用代码
4. 点击"确定"按钮，验证表单
5. 系统自动生成客户编号
6. 跳转到客户详情页（编辑模式），继续完善客户信息

**查看客户流程**：
1. 用户在列表页点击客户编号或"查看"按钮
2. 跳转到客户详情页（查看模式）
3. 展示客户完整信息（基本信息、组织架构、联系人、业务历史等）

**编辑客户流程**：
1. 用户点击"编辑"按钮
2. 跳转到客户详情页（编辑模式）
3. 用户修改客户信息
4. 点击"保存"按钮，系统保存修改

**删除客户流程**：
1. 用户点击"删除"按钮
2. 弹出确认对话框："确定要删除客户"XXX"吗？"
3. 系统校验客户是否被业务引用（商机、方案、合同等）
4. 如已被引用，提示"该客户已有业务记录，无法删除"，禁止删除
5. 如未被引用，执行删除操作
6. 刷新列表页，显示成功提示

**批量删除客户流程**：
1. 用户勾选需要删除的客户（复选框）
2. 点击"批量删除"按钮
3. 弹出确认对话框："确定要删除选中的 N 个客户吗？删除后不可恢复。"
4. 系统校验所有选中客户是否被业务引用
5. 如有客户被引用，提示具体哪些客户无法删除
6. 如全部可删除，执行批量删除操作
7. 刷新列表页，显示成功提示，清空选中状态

#### 五、业务规则

- 客户名称必填且不能重复
- 统一社会信用代码如填写则必须唯一
- 客户编号自动生成，格式：CUS-YYYYMMDD-XXX（CUS=Customer）
- 删除客户需校验是否被商机、方案、合同、项目引用
- 批量删除时，逐个校验每个客户是否可删除
- 批量删除按钮在未选中客户时为禁用状态
- 同一客户名称不可重复创建
- 列表默认按创建时间降序排列
- 客户状态可选：潜在客户、意向客户、合作中、已流失
- 客户级别可选：重点客户、普通客户、潜在客户
- 导出按钮固定在右上角位置

## 10. 验收标准

| 验收项 | 验收标准 |
|--------|----------|
| 界面一致性 | 所有页面UI风格一致、字段对齐、布局合理 |
| 数据准确性 | 客户信息、组织架构、联系人数据准确无误 |
| 权限控制 | 不同角色访问权限符合预期，数据隔离有效 |
| 性能要求 | 列表查询响应时间 < 2s，树形结构加载响应时间 < 1s |
| 功能完整性 | 所有功能点均可正常使用，覆盖所有业务场景 |
| 组织架构管理 | 树形结构展示正确，层级关系清晰，操作流畅 |
| 联系人管理 | 联系人信息完整，主要联系人标识清晰，与部门关联正确 |
| 业务历史 | 业务记录自动同步，表格展示正确，统计数据准确 |
| 异常处理 | 异常情况有友好提示，不影响系统稳定性 |
| 兼容性 | 支持Chrome、Edge、Firefox等主流浏览器 |

   - [ ] 支持多层级部门嵌套（至少10层）

   - [ ] 树形结构展示正确，层级关系清晰
