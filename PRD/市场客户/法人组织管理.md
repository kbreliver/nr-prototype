## 2. 功能目标与核心价值

### 2.1 功能目标

法人组织存在独立法人、跨集团、多层级、多业务的复杂关系，现有客户管理难以覆盖这些维度。法人组织管理模块的目标是：

**主要目标：**
- 建立完整的法人组织层级管理体系，支持集团-公司-子公司-工厂等多级结构的可视化维护；
- 提供多维度查询（关键字、信用代码、组织类型、数据来源）与导出能力，帮助用户快速定位目标组织；
- 支持法人组织与客户档案的灵活关联，自动带出法人基础信息，加快客户创建与更新流程；
- 提供组织管理页的树形视图与明细面板，让用户在同一页面内完成添加子组织、编辑、删除、客户关联等操作；
- 与第三方（企查查、天眼查等）数据源衔接，保障信息及时更新并提供补充入口。

### 2.2 核心价值

**对客户（内部用户）：**
- 减少重复录入与信息漏记，通过统一的法人组织信息库快速完成客户创建与组织检索；
- 通过集团视图及标签化状态判断是否已经关联客户，降低跨角色协作成本；
- 规范操作流程（新建→管理→详情），提升日常批量操作效率。

**对公司：**
- 形成覆盖全国的法人组织信息体系，避免信息孤岛；
- 提高数据准确性，自动生成编号、格式校验，降低人工错误；
- 为客户、合同等业务提供统一参考数据，支撑分析与决策。

**对集团：**
- 建立统一的法人组织管理标准，便于资源整合与跨集团协同；
- 通过客户关联状态提供集团客户画像，提升管理层运营洞察；
- 支持集团内部的分级权限与角色协作机制。

## 3. 业务背景与使用场景

### 3.1 背景说明

在客户管理过程中，许多客户本身属于具备独立法人资质的集团公司体系。集团-子公司-工厂等层级呈树形结构，既独立运营又在业务上相互关联。客户内部的部门（内部组织）与法人组织概念不同，但在业务中对同一数据源有多次引用，容易造成重复录入、数据错配与权限混乱。为满足复杂层级的查询、客户关联、审批流、第三方数据同步等需求，法人组织管理模块作为客户基础信息的底座十分必要。

### 3.2 使用场景

| 场景编号 | 场景名称 | 场景说明 | 典型用户 |
|---------|---------|----------|---------|
| S01 | 新建法人组织 | 在系统中新增集团或公司，为后续管理提供入口 | 业务人员 / 管理员 |
| S02 | 组织层级维护 | 管理组织之间的上下级关系与结构变动 | 组织管理员 / 业务经理 |
| S03 | 客户关联 | 将法人组织关联到客户档案并自动填充基础信息 | 客户经理 / 客户专员 |
| S04 | 集团视图查询 | 查看某一集团下的所有法人组织与客户分布 | 业务经理 / 管理层 |
| S05 | 组织数据查阅 | 快速检索法人编号、信用代码或名称，并查看详情 | 业务人员 / 销售支持 |
| S06 | 第三方更新 | 触发与企查查、天眼查的同步，补全缺失字段 | 业务人员 / 数据运维 |

## 4. 用户角色与职责

| 角色 | 职责 | 权限范围 |
|------|------|----------|
| 业务人员 | 创建搜索法人组织、维护资料、关联客户档案 | 创建并编辑自己负责的法人组织 |
| 业务经理 | 维护本部门/本集团组织结构、管控客户量级 | 查看/管理本部门或本集团数据 |
| 专员 | 补充法人基础信息、维护行业与地址细节 | 查看/编辑非核心字段，不允许删除核心记录 |

| 管理员 | 配置权限、修复数据、维护组织体系 | 超级权限，支持全量操作 |

## 6. 功能需求说明

**说明**：每个页面独立成一个小节，按功能说明、UI示意、功能点、关键流程、业务规则、字段定义组织结构。

### 6.1 页面1：法人组织列表页（根节点列表）

#### 一、页面功能说明

展示所有根节点（集团/总部/公司）及基础统计，支持筛选、排序、分页与批量操作，帮助用户快速定位目标法人组织。

#### 二、UI 示意（留图区域）

```

│  ┌──────────────┐ ┌──────────┐ ┌──────────┐ ┌────────────┐              │

├───────────────────────────────────────────────────────────────────────────┤
│ □ 编号↑│名称│信用代码│法定代表人│注册资本│下属组织数│客户数量│数据来源│操作                        │

│ ...                                                                      │
└───────────────────────────────────────────────────────────────────────────┘

#### 三、功能点说明

- 支持按关键字（编号、名称、信用代码）、组织类型、数据来源等维度筛选；
- 关键字支持模糊匹配，匹配编号与名称；
- 每行前提供复选框，支持全选、批量删除与批量导出；
- 默认按创建时间倒序，可对重要列进行排序；
- 操作列包含“管理”“删除”按钮，管理跳转组织管理页；
- 导出按钮固定在右上角，与其他列表保持一致；
- 新建采用弹框方式，核心字段填写后跳转详情页续填。

#### 四、关键操作流程

**新建流程**
1. 点击“新建根组织”；2. 弹出弹框填写核心字段；3. 点击“确定”；4. 系统生成编号；5. 跳转组织详情页（编辑模式）继续完善。

**管理流程**
1. 点击“管理”按钮；2. 跳转组织管理页；3. 左侧树形展示完整结构；4. 右侧展示当前节点详情；5. 可添加子组织或创建客户。

**删除流程**
1. 点击“删除”按钮；2. 校验是否存在下属组织或客户；3. 若可删，弹出确认；4. 操作成功后刷新列表；5. 若不可删，展示具体提示。

**批量删除流程**
1. 勾选多条数据；2. 点击“批量删除”；3. 系统逐条校验；4. 全部可删时执行删除并刷新；5. 出现问题的数据提示具体原因。

#### 五、业务规则

- 组织名称必填且不可重复；
- 组织编号自动生成，格式：LE-YYYYMMDD-XXX；
- 删除需校验是否存在下属组织或已关联客户；
- 批量操作需逐条校验，有问题的数据点显示提示；
- 列表默认按创建时间降序，可提供额外排序；
- 导出按钮位置与设计规范保持一致；
- 已关联客户的节点在列表中显示客户数量提示。

| 法定代表人 | 字符串 | 否 | 长度30 | 姓名 |
| 注册资本 | 字符串 | 否 | 长度20 | 例如“100000万元” |

#### 三、功能点说明

- 左侧树形展示根组织及其所有下属，支持展开/收起；
- 选择节点后右侧展示基本信息、组织层级、关联客户状态；
- 已创建客户的节点附带绿色“客户✓”标签；
- 顶部提供“添加子组织”按钮，支持在当前上下文直接新增；
- 右侧提供“编辑”“从第三方更新”“删除”等操作，根据条件启用；
- 支持“创建客户”跳转，自动填充法人基础信息；
- 关联客户模块还提供集团内客户列表与快速跳转。

#### 四、关键操作流程

**添加子组织流程**
1. 选中上级节点；2. 点击“添加子组织”；3. 弹出对话框填写信息；4. 点击“确定”；5. 树形结构刷新；

**创建客户关联流程**
1. 选中尚未关联客户的组织节点；2. 点击“创建客户”；3. 跳转客户新建页，自动带出法人信息；4. 客户保存后该节点标记为已关联；

**查看客户详情流程**
1. 点击右侧关联客户名称；2. 跳转客户详情页；3. 展示完整客户信息与业务状态。

#### 五、业务规则

- 所有非根节点必须设置上级组织；根节点仅限集团总部/公司；
- 不得将组织自身或子节点设置为上级，防止循环引用；
- 节点存在下属组织或已关联客户时不可删除；
- “创建客户”按钮仅在未关联客户时可用；
- 添加子组织后立即刷新树形结构；
- 第三方更新需要组织具有信用代码与必要字段；
- 客户数量与关联状态在树形与右侧详情中同步展示。

| 组织名称 | 字符串 | 是 | 法人名称 |
| 组织类型 | 枚举 | 是 | 集团、公司、子公司、分公司、办事处、工厂 |
| 上级组织ID | 整数 | 否 | 上级节点 |
| 上级组织名称 | 字符串 | 否 | - |
| 组织层级 | 整数 | 是 | 1、2、3... |
| 组织路径 | 字符串 | 否 | 全路径 |
| 是否关联客户 | 布尔 | 是 | 标识 |
| 客户ID/编号/名称 | 字符串 | 否 | 关联客户信息 |

展示单个组织节点的全部属性（包括基本信息、组织层级、关联客户），支持查看、编辑、删除以及客户跳转操作。

#### 二、UI 示意（留图区域）

```
┌───────────────────────────────────────────────────────────────────────────────┐
│  ← 返回  XX科技有限公司                                           [编辑] [删除]       │
│  编号：LE-20240615-001  [子公司] [已关联客户] [手动录入]                          │
├───────────────────────────────────────────────────────────────────────────────┤
│  [基本信息] [组织层级] [关联客户]                                  │
├───────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  基本信息（编号、名称、信用代码、注册资本、成立日期、注册地址、行业、电话） │

└───────────────────────────────────────────────────────────────────────────────┘

#### 三、功能点说明

- 页面顶部展示组织名称、编号、组织类型与客户状态；状态以标签形式呈现；
- 详情分为多个区块（基本信息、组织层级、关联客户）；
- 编辑模式提供表单字段、保存/取消按钮，且字段均带校验（如信用代码格式）；
- 删除受限：仅当无下属组织/客户/业务引用时才可执行；
- 关联客户块展示集团内其它客户并提供跳转入口；
- 客户信息采用卡片式展示，支持跳转客户详情页。

#### 四、关键操作流程

**查看详情流程**
1. 在列表页或组织管理页点击编号/“查看”；2. 跳转详情页；3. 展示完整信息；4. 可点击“编辑”切换模式。

**编辑流程**
1. 点击“编辑”；2. 字段由只读切换为可编辑；3. 修改并点击“保存”；4. 通过校验后保存并返回查看；5. 点击“取消”恢复原值。

**删除流程**
1. 点击“删除”；2. 校验是否存在子组织/客户/业务记录；3. 若可删，弹窗确认；4. 确认后删除并返回列表页；5. 若不可删，提示“该数据已有业务记录，无法删除”。

#### 五、业务规则

- 编号固定且不可修改；
- 组织名称必填且在上下级结构内不能重复；
- 根节点只能是集团总部/公司，必须有创建人/创建时间；
- 查看模式下字段只读，编辑模式需完成信用代码格式校验；
- 已关联客户的节点在列表、树、详情中同步显示“客户✓”；
- 若客户已删除，在组织详情中提示“客户已失效”；
- 删除仅允许在无下属与客户的情况下执行。

#### 六、字段定义

与第6.1/6.2中字段一致，可拓展填写经营范围、甚至关联客户编号/名称等内容。

## 8. 权限与角色配置

| 角色 | 列表查看 | 新增 | 编辑 | 删除 | 其他操作 |
|------|----------|------|------|------|----------|
| 业务人员 | ✔️ | ✔️ | ✔️（自己负责的） | ❌ | ✔️（部分） |
| 业务经理 | ✔️ | ✔️ | ✔️（本部门） | ✔️（本部门） | ✔️（部分） |
| 专员 | ✔️ | ❌ | ✔️（部分字段） | ❌ | ❌ |
| 项目经理 | ✔️ | ❌ | ✔️（项目相关） | ❌ | ✔️（部分） |
| 管理层 | ✔️ | ❌ | ❌ | ❌ | ❌ |
| 管理员 | ✔️ | ✔️ | ✔️ | ✔️ | ✔️ |

**说明**
- 业务人员只能查看与编辑自己负责的数据；
- 业务经理可管理本部门/本集团数据；
- 专员只能维护非核心字段，不能删除核心节点；
- 项目经理侧重项目级视图与标签；
- 管理层仅能查看数据，不能编辑；
- 管理员为超级权限，可执行所有操作。

   - [ ] 唯一性字段校验生效；

   - [ ] 组织树展示清晰；
   - [ ] 不允许设置会导致循环引用的上级组织；

   - [ ] 详情页加载时间 < 1 秒；
